# Data Flow

End-to-end lifecycle of an IMAS standard name, from Data Dictionary path to published catalog.

## Pipeline Overview

```
DD paths ──▶ codex mint ──▶ graph ──▶ publish ──▶ YAML catalog ──▶ human review ──▶ ISN build ──▶ .db dist ──▶ docs + API
```

## Stage Details

### 1. DD Path Analysis (imas-codex)

imas-codex reads the IMAS Data Dictionary to discover paths that need standard names. It uses ISN's grammar context (`get_grammar_context()`) to understand naming rules before generating candidates.

### 2. Name Minting (imas-codex)

Candidates are generated by applying ISN's grammar rules to DD path semantics.
imas-codex reads registry-derived templates and vocabulary from
`get_grammar_context()`, then submits every candidate to
`parse(name, strict=True)`. That call is the authority for both flat names and
recursive ordered operator trees.

The default `parse(name)` mode and `validate_round_trip(name)` are diagnostic
tools and cannot promote a candidate. `parse_standard_name(name)` is used only
when a strict-valid result must also project into the flat `StandardName`
facade. A nested binary expression can pass strict validation and still be
unrepresentable in that facade.

### 3. Graph Organization (imas-codex)

Related candidates are organized into a dependency graph for batch review. This helps domain experts review names in logical groups.

### 4. Publish Candidates (imas-codex)

Candidates are published as pull requests to the [imas-standard-names-catalog](https://github.com/iterorganization/imas-standard-names-catalog) repository.

### 5. Human Review (catalog repository)

Domain experts review proposed names for:

- Physics correctness
- Naming quality and clarity
- Completeness of metadata (unit, description, physics_domain)
- Consistency with existing catalog entries

### 6. ISN Catalog Build (this project)

Once YAML files are merged, ISN builds the catalog:

- Ingests YAML source files
- Runs strict grammar validation with `parse(name, strict=True)`
- Projects names into flat fields only where the consuming catalog surface
  requires that representation
- Runs structural and semantic catalog checks
- Produces a SQLite `.db` file
- The `.db` is distributed as part of the `imas-standard-names-catalog` package

### 7. Read Access (this project)

ISN loads the `.db` and exposes it two ways:

- **Python API**: package-level `parse`, `compose`, and `StandardNameIR` for
  lossless grammar work; `parse_standard_name` for strict flat projection;
  `get_grammar_context` for machine-readable rules; and
  `StandardNameCatalog` for catalog query
- **Documentation site**: the published grammar reference and catalog browser

Model Context Protocol tools over the same data are served by **imas-codex**,
which calls this API.

## Where Each Project Fits

| Stage | Project | Role |
|-------|---------|------|
| DD analysis, minting, graph, publish | **imas-codex** | Generates candidate names using ISN grammar |
| YAML source files, human review | **imas-standard-names-catalog** | Stores approved names as reviewed YAML |
| Grammar, validation, catalog build, docs site | **imas-standard-names** (this project) | Defines grammar, builds catalog, publishes docs and API |
