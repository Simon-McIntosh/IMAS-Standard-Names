Plan · grammar · consumer: imas-codex S18

One definition per concept

The grammar says how a name is spelled. Nothing says how the shared ideas inside a name are defined. So the catalog writes the flux-surface average five ways and glosses the plasma boundary as the separatrix. This plan adds that missing layer beside the vocabularies it is keyed by, and releases it with them.

§1 — Why here, and why now

The imas-codex consistency census of 2026-10-12 (imas-codex:sn-catalog-consistency-census) measured 72 accepted entries re-deriving the flux-surface average, in five notations and with one wrong. 24 boundary entries call the plasma boundary the separatrix, and the WEST batch opens its documentation in four styles. The consumer plan imas-codex:sn-house-style authors a single house style to fix this. On 2026-10-12 the lead ruled that the house style lives in ISN now, released before the WEST re-cut, rather than in imas-codex first. A definition belongs with the grammar that names the thing defined, and every consumer of the standard should see it, not only the generator.

Existing guidance is the base, not a competitor. docs/guidelines.md states naming rules and the flux-surface-average tag. The shipped symbol definition policy requires every symbol to be defined by identity and name link. The locus registry already carries a definition per locus. The new layer adds what none of them hold: one canonical equation per concept, one symbol per quantity, and one opening template per name pattern.

§2 — The registry and its loader

Three files under imas_standard_names/grammar/vocabularies/conventions/:

  • concepts.yml — one entry per shared concept, keyed by the operator, locus, coordinate or base token that carries it. Each entry holds a canonical phrase, a one-sentence definition, exactly one canonical LaTeX equation, its symbol table, forbidden variants as patterns, and whether a name using it restates the equation or only names the concept.
  • notation.yml — one symbol per quantity or coordinate, keyed by base, subject, component or coordinate token, with its forbidden spellings.
  • templates.yml — one description opening and one documentation opening per name pattern, the section order, and the sign-convention rule by COCOS transformation type.

A pydantic model and a loader live beside the existing vocabulary loaders. The loader refuses any key that is not a real token in the current vocabularies, so the registry cannot drift from the grammar. A public accessor takes a parsed name and returns exactly the entries that apply to it.

Done when: the loader validates all three files and refuses one deliberately malformed entry per file, plus one entry keyed by a token that does not exist, each failing by name. For flux_surface_averaged_argon_density_at_plasma_boundary, the accessor returns the flux-surface-average concept, the plasma-boundary entry, the density notation and the species-density template, and nothing else.

§3 — The entries the WEST batch needs

Content is authored by the coordinator under imas-codex:sn-house-style §3 and lands here. The lead's rulings of 2026-10-12 fix three entries before any other is written:

  • The flux-surface average is defined by the surface form, \langle f\rangle = \oint f\,dS/|\nabla\psi| \,/\, \oint dS/|\nabla\psi|. The line form may be named as equivalent in prose and is never written as a second equation.
  • The plasma boundary is "the last closed flux surface". The separatrix is named only where a quantity is defined for a diverted configuration.
  • Every documentation entry opens with a defining noun phrase, the same shape as its description.

Done when: every concept, symbol and pattern used by the 220 names of the frozen WEST roster has an entry. The worklist is produced by running the §2 accessor over that roster and listing the tokens it finds with no entry, so the list is measured, not guessed. The lead has read concepts.yml.

§4 — Released before the WEST re-cut

imas-codex already consumes this repository as an editable path source, so the registry is usable there the moment it lands on main. The release is what makes it part of the published standard. Cut it with standard-names release before the WEST candidate is cut. In imas-codex, both imas-standard-names pin occurrences move together, and the graph's grammar snapshot is verified to carry the release rather than assumed, since a scoped run does not resync it.

Done when: the tag is published and installable from the package index. Both imas-codex pin lines name it. A read of the graph's grammar snapshot reports the released version.
