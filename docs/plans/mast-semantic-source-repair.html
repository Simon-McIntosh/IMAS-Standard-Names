MAST Standard Name semantic source repair

This plan repairs the distinction that matters: a Standard Name is the stable semantic identity; a DD path or MAST signal is an sn-source that provides provenance for that identity. A source defect is not automatically a naming defect. The graph and catalog remain read-only until publication authority is given.

Six object-specific identities are absent from both the live graph query and the current ISNC release candidate.

Wrong attachments confirmed

Iron-core and flux-surface names are attached to different physical objects.

MAST signal sources zero roots

get_facility_coverage("MAST") returns no discovery roots or scored paths.

Publication authority required

Manifest, grammar checks and dry runs may proceed; graph apply and ISNC release may not.

Current read-only evidence

The baseline was refreshed through the current imas-cx MCP server rather than copied from the earlier ledger. The server is operational. It reports no MAST facility discovery roots, no coverage categories and zero scored paths. Standard Name search/fetch and provenance tracing also expose three separate states that must not be collapsed:

  1. Definition correct, source wrong: the name and description describe one object, but a source edge points at a different DD object.
  2. Definition too generic for an object-specific DD leaf: the description is not literally false, but it loses the active-coil/passive-loop/vessel distinction and breaks the expected R/Z pair family.
  3. Name absent: no exact record exists to receive the correct source edge. This is the genuinely SN-side part of the work.

Most graph DD sources still cite 4.1.0, while Nova authors 4.1.1. A version refresh is required even where the name and path association is otherwise correct. It is a provenance validation step, not a request to invent different semantics.

Experimental sources are a separate missing layer

The zero MAST coverage result is source-side. It does not imply that all MAST concepts need new Standard Names. The facility layer should add typed signal, analysis_code, experimental_data, data_access and documentation sources for the existing semantic identities. Priority roots are FAIR-MAST L1/L2 Zarr, the JSON shot-metadata API, UKAEA MAST open-data records, vacuum-shot selections, diagnostic channel documentation and the equilibrium-analysis code that interprets those signals.

Signal sources carry facility, accessor, channel, shot range, units, sign/calibration convention and processing level. They support the Nova generate/refine loop and make experimental provenance queryable. They must never replace the DD source for a Data Dictionary concept, and a channel name must never be promoted into a globally scoped Standard Name.

Execution stages

  1. Freeze an exact focus manifest. Enumerate every MAST machine-description DD path and record expected name, current graph identity/stage, complete sources, ISNC presence, DD 4.1.1 documentation and MAST facility coverage. Store a digest and the imas-codex, ISN and ISNC commits used.
  2. Adjudicate names in ISN. Parse and round-trip the six candidates, confirm their physical-base/subject construction, object-specific family policy, units and COCOS transformation. If a proposed spelling fails grammar or collides with an existing semantic identity, resolve it here before graph work.
  3. Prepare a targeted imas-codex transaction. Express exact detach/attach/create operations for only the focus manifest. Guard against cross-object leaf-name grouping, distinct-vector conflicts, stable-id replacement and DD-version drift. Do not invoke a broad reconciliation or catalog rebuild.
  4. Add facility source discovery. Define MAST discovery roots, manifest the vacuum and diagnostic signals needed by Nova, and run source-unwind checks read-only before any source application.
  5. Validate before authority. Run strict ISN parse/compose, source-invariant, stable-id graph/catalog diff and dry-run export gates. Produce an exact proposed delta and stop.
  6. Apply after authority. With explicit permission, apply one scoped graph transaction, export one ISNC release candidate, validate the catalog, pin the exact artifacts and re-query through imas-cx. No hand editing of catalog YAML.

Acceptance and negative gates

  • Every focus DD path has exactly one semantically compatible accepted identity or one explicit reviewed non-nameable disposition.
  • No name's description changes merely to accommodate a wrong source. Correct definitions are preserved while edges move.
  • R/Z leaves for the same component resolve to the same object-specific semantic family.
  • No graph-only accepted identity disappears from the release candidate, and no ISNC record is restored with incomplete sources.
  • DD sources validate at 4.1.1 and carry the correct COCOS transformation; no stale 4.1.0 URL is treated as current evidence without revalidation.
  • MAST facility coverage is non-empty, but facility signals do not mint facility-specific Standard Names or replace DD provenance.
  • Without explicit publication authority the terminal artifact is a dry-run manifest and proposed delta. Any graph or catalog mutation is a failure.

§ Decisions

What is the relationship between a Standard Name and an sn-source?

A Standard Name is the stable semantic identity. DD paths and facility signals are provenance sources that realize it; they are not the name and do not define a catalog map.

Locked by the lead: SNs are standard names, not catalog maps. A name may be correctly defined while a DD-path or signal source edge is absent or wrong.

Read-only graph and catalog inspection is authorized. Catalog mutation is not.
